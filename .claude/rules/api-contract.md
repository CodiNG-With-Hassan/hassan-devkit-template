## Generated API types & client (`libs/api-types`, `libs/api-client`)

The FE apps consume the API contract from two generated packages, both derived from the same
committed OpenAPI spec (`libs/api-types/spec/openapi.json`):

- `api-types` — framework-agnostic request/response types (`src/generated/api.d.ts`), consumed
  as a regular `workspace:*` dependency.
- `api-client` — Angular `HttpClient` repositories generated by orval (one `*Repository` per API
  tag: `HealthRepository`, …). Shared **as source** via the `@ApiClient`
  tsconfig path alias (never built), consumed by every web app and by `libs/web-ui`. The repositories issue relative
  URLs; each app's `apiBaseUrlInterceptor` prefixes `environment.apiUrl`. The package's
  `dependencies` mirror the apps' Angular/rxjs ranges — **bump every web app, `libs/web-ui` and
  this package together**, or pnpm installs duplicate framework instances and dev breaks with NG0203 (see
  `libs/api-client/README.md`).

After any change to API DTOs, entities, or controller response decorators:

1. Make sure the dev stack is running (the spec is fetched from this checkout's `API_SPEC_URL`,
   `http://localhost:3000/api-json` on slot 0; the `@nestjs/swagger` CLI plugin only runs inside
   `nest start`/`nest build`, so the spec cannot be produced by a side-build).
2. Run `pnpm api:types` from the root (regenerates the spec, `api-types`, and `api-client`) and
   commit the regenerated files with the API change.

`pnpm api:types:check` regenerates both packages from the committed spec and fails on drift
(CI-safe, no running API needed). Never hand-edit the `src/generated/` folder of either package;
`libs/api-client/src/index.ts` is a hand-written barrel — extend it when a new API tag appears.

A pre-commit guard (`scripts/pre-commit-extra.sh`) enforces this offline: committing contract
files (entities, DTOs, controllers, `nest-cli.json`, the `ErrorCode` enum) without the spec is
rejected, and staged spec/generated changes are verified by regenerating from the staged spec. Override for
contract-neutral API refactors: `SKIP_API_SPEC_CHECK=1 git commit`.

New API endpoints must declare a response `type` on their `@ApiOkResponse`/`@ApiCreatedResponse`
decorator (entities or `*-response.dto.ts` classes) —
otherwise the response is untyped in the spec and the FE gets no model for it.
