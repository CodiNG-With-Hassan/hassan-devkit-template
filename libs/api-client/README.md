# api-client

Angular HTTP services generated by [orval](https://orval.dev) from the API's OpenAPI spec
(`libs/api-types/spec/openapi.json` — the committed spec owned by `api-types`). One injectable
repository per API tag (`HealthRepository`, …), returning typed
`Observable`s via `HttpClient`. orval generates `*Service`/`*.service.ts` names; the
`rename-to-repositories` step in `pnpm generate` converts them to the workspace's
`*.repository.ts` convention.

## How it is consumed

The package is **shared as source, not built**: consumers map the `@ApiClient` alias in their
`tsconfig.json` to `libs/api-client/src/index.ts`, so the generated code is compiled by the
app's own build. This only works for apps on the **same Angular major as this package's
dependencies** — every web app (Angular 22).

```ts
import { HealthRepository } from '@ApiClient';

private readonly healthRepository = inject(HealthRepository);
this.healthRepository.check(); // Observable<HealthResponse>
```

The generated services issue **relative URLs** (`/api/health`). Each consuming app registers an
`apiBaseUrlInterceptor` (see `core/interceptors/`) that prefixes them with
`environment.apiUrl`; requests to `/assets/**` and absolute URLs are left alone.

In the dev stack `libs/` is bind-mounted at `/workspace/libs`, so the alias resolves inside the
containers exactly as it does on the host.

### The version contract (important)

This package declares real `dependencies` on `@angular/common`, `@angular/core`, `rxjs`, and
`tslib`, **mirroring the web app's ranges exactly**. Because the workspace has a single
lockfile, pnpm dedupes them to the *same physical copies* the web app uses — which is what
makes plain module resolution work from `libs/` (pnpm does not hoist) and keeps vite/esbuild
seeing a single framework instance.

That means: **when the web app's Angular/rxjs versions are bumped, bump this package's
dependencies in the same change.** If they drift apart, pnpm installs two framework instances
and the dev server fails at runtime with `NG0203` (duplicate `@angular/core`). Renovate updates
that group Angular across the workspace are safe; partial bumps are not.

## Regenerating

`pnpm api:types` from the root regenerates the spec, `api-types`, and this client in one go
(dev stack must be running). To regenerate only this client from the committed spec:
`nx run api-client:generate`. `nx run api-client:check` fails on drift (CI-safe).

Never hand-edit `src/generated/`. `src/index.ts` is the hand-written barrel — add a line when a
new API tag appears.
